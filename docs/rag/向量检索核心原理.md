# 向量检索核心原理
## 一、向量检索的本质
向量检索的核心是：给定一个查询向量，在海量向量库中快速找到距离最近的 N 个向量，对应找回最相关的文本片段。
RAG 中的完整映射关系：
- 用户问题 → 查询向量
- 知识库分片 → 库向量 + 原始文本 + 元数据
- 向量距离 → 语义相关性
- 距离最近的 Top-N 向量 → 最相关的 Top-N 文本片段

## 二、暴力精确检索 vs 近似最近邻（ANN）
### 1. 暴力精确检索（Brute Force）
- 原理：查询向量和库里所有向量逐一计算相似度，全量比较后排序
- 优点：100% 精确，结果完全可复现，没有误差
- 缺点：数据量越大越慢，O(n) 线性复杂度，百万级以上完全不可用
- 适用场景：小数据集（<1万条）、原型验证、效果对比测试

### 2. 近似最近邻（ANN - Approximate Nearest Neighbor）
- 核心思想：提前对向量库建立索引，检索时通过索引快速缩小搜索范围，牺牲极小的精度换取几十上百倍的速度提升
- 精度损失：通常召回率 95%~99%，语义检索场景完全可接受
- 常见索引类型：
  - HNSW：业界标配，分层跳表结构，平衡速度、精度、内存消耗，绝大多数向量库默认索引
  - IVF：聚类分桶，适合海量数据、内存有限的场景
  - PQ：乘积量化，压缩向量体积，适合超大规模数据集

### 3. RAG 场景选型结论
- 学习、原型、小知识库：暴力检索足够，简单可控
- 生产、万级以上分片：必须用 ANN 索引，否则检索延迟不可接受

## 三、两大核心参数：Top-K 与相似度阈值
### 1. Top-K 召回数量
- 定义：一次性召回相似度最高的 K 个结果
- 作用：控制召回结果的数量，平衡信息完整性和噪声占比
- RAG 常用取值：3~10
  - K=1~2：信息容易不全，答案跨分片时直接漏召回
  - K=3~5：平衡区间，绝大多数场景的最优解
  - K>10：引入大量无关内容，稀释有效信息，还容易超 Token 上限

### 2. 相似度阈值
- 定义：最低相似度门槛，低于阈值的结果即使在 Top-K 里也丢弃
- 作用：兜底过滤完全不相关的结果，避免垃圾内容进入 Prompt
- RAG 常用取值：0.6~0.8（随模型不同略有差异）
  - 阈值太高：召回率下降，很多相关内容被过滤掉
  - 阈值太低：精确率下降，大量无关内容混入

### 3. 最佳实践：两者配合使用
先按 Top-K 宽召回，再用相似度阈值精筛。
查询向量 → 召回 Top20 候选 → 过滤掉相似度 < 0.7 的 → 最终返回 Top5
既保证不会漏掉相关结果，又保证最终结果的质量。

## 四、检索效果评价：召回率 vs 精确率
### 1. 定义
| 指标 | 公式 | 含义 | RAG 中的影响 |
|---|---|---|---|
| 召回率 Recall | 召回的正确结果 / 所有正确结果 | 有没有漏 | 低了会缺信息，导致模型幻觉 |
| 精确率 Precision | 召回的正确结果 / 所有召回结果 | 准不准，垃圾多不多 | 低了会引入噪声，干扰模型回答 |

### 2. 权衡关系
召回率和精确率本质是零和博弈：
- 调大 TopK、降低阈值 → 召回率↑，精确率↓
- 调小 TopK、提高阈值 → 精确率↑，召回率↓
没有同时最高的方案，只能根据业务场景找平衡点。

### 3. RAG 场景的权衡策略
- 第一层：宽召回：向量检索阶段适当放大 TopK（10~20），优先保证召回率，别漏答案
- 第二层：精筛：通过阈值过滤、Rerank 重排序，把无关的去掉，提升精确率
- 最终目标：送入 LLM 的 3~5 个片段，既全又准

## 五、进阶优化：MMR 最大边际相关性
### 1. 解决的痛点
普通 TopK 检索只看相关性，容易出现：
- 同一个意思的句子重复出现在多个分片里，全部排在前面
- 结果高度同质化，信息冗余，浪费 Token
- 多角度的答案被淹没，只返回一种表述

### 2. 核心思想
在「和查询的相关性」和「与已选结果的差异性」之间找平衡，既保证相关，又避免重复。

### 3. 公式
$$MMR = \lambda * Sim(query, doc) - (1-\lambda) * max( Sim(doc, selected\_docs) )$$
- λ：权重系数，取值 0~1
  - λ=1：完全只看相关性，等于普通 TopK
  - λ=0：完全只看多样性，和查询无关
  - RAG 推荐值：0.7~0.8，优先保证相关性，兼顾多样性
- Sim(query, doc)：文档和查询的相似度
- max(Sim(doc, selected_docs))：文档和已选结果的最大相似度

### 4. 执行流程
1. 从候选集中选 MMR 值最高的一个，加入结果集
2. 重新计算剩下所有候选和已选结果集的最大相似度
3. 重复直到选够 K 个或没有符合阈值的候选

### 5. RAG 中的收益
- 减少重复内容，节省 Token
- 提升答案的信息密度，多角度覆盖问题
- 避免同一个观点被反复提及
